# NewLife.BACnet 需求文档

## 1. 背景与目标

### 1.1 背景

BACnet（Building Automation and Control Networks）是由 ASHRAE 制定的楼宇自动化标准协议（ANSI/ASHRAE Standard 135 / ISO 16484-5），广泛应用于暖通空调（HVAC）、照明、安防、能源管理等楼宇自动化领域。主流设备厂商（约翰逊控制、霍尼韦尔、西门子楼宇、施耐德等）均提供 BACnet 兼容设备。

.NET 生态中已有 [ela-compil/BACnet](https://github.com/ela-compil/BACnet)（原 YABE 内置协议库）等实现，但缺乏一个维护活跃、支持新版框架、且深度集成物联网平台的 BACnet 协议库。NewLife.BACnet 在 ela-compil/BACnet 基础上，对协议核心进行重构，并构建了面向 IoT 边缘场景的高级 API 层，旨在提供纯托管代码的高质量 .NET BACnet 协议栈。

### 1.2 愿景目标

**成为 .NET 生态中功能最完整、最易集成的 BACnet 协议库**，让楼宇自动化工程师和 IoT 边缘开发者能够用最少的代码实现设备发现、数据采集、属性写入和事件处理，并无缝对接 NewLife IoT 物联网平台生态，成为楼控系统与 IoT 平台之间的可靠桥梁。

### 1.3 可衡量目标

- **简洁 API**：客户端 10 行代码内完成设备发现和属性读取；服务端 15 行代码内暴露可被第三方楼控系统访问的 BACnet 设备
- **完整协议栈**：支持 ASHRAE 135 标准定义的 30 种确认型服务和 15 种未确认型服务，与 YABE 等主流工具互操作验证通过
- **双模式运行**：同一库既可作 BACnet 客户端（采集/写入设备），又可作 BACnet 服务端（向外暴露设备），无需两套代码
- **IoT 生态集成**：作为 `NewLife.IoT` 标准驱动，与 Modbus、西门子 PLC 等驱动在同一框架下统一管理
- **多框架兼容**：`netstandard2.0` + `net45` 双目标框架，覆盖 .NET 4.5 至 .NET 9+，无需本地库依赖
- **可观测**：全链路 `ITracer` APM 追踪和 `ILog` 日志，关键操作耗时可接入 Stardust 等监控平台

| 角色 | 说明 | 核心诉求 |
|------|------|---------|

## 3. 功能需求

### 3.1 M1 - 传输层

**描述**：提供不同物理/网络媒体的 BACnet 数据传输能力。

**用户故事**：作为楼宇自动化工程师，我希望通过以太网 IP 网络连接 BACnet 设备，以便不需要特殊硬件即可集成。

**验收条件（AC）**：
- [x] 支持 BACnet/IP (IPv4) UDP 传输，默认端口 47808（0xBAC0）
- [x] 支持 BACnet/IP (IPv6) UDP 传输
- [x] 支持 BBMD（BACnet Broadcast Management Device）广播管理
- [x] 支持外部设备（Foreign Device）向 BBMD 注册
- [x] 传输层通过 `IBacnetTransport` 接口抽象，支持自定义扩展
- [ ] 支持 MS/TP (RS485) 串口传输，用于现场总线设备
- [ ] 支持 PTP (RS232) 点对点串口传输
- [ ] 支持以太网（Ethernet 802.3）直连传输

**优先级**：BACnet/IP = Must；MS/TP = Should；PTP/以太网 = Could

---

### 3.2 M2 - 协议编解码

**描述**：实现 BACnet 各层协议的编码和解码，确保与标准设备的互操作性。

**用户故事**：作为 .NET 库维护者，我希望编解码层完全遵循 ASHRAE 135 标准，以便与所有合规设备正常通信。

**验收条件（AC）**：
- [x] 实现 ASN.1 BER（Basic Encoding Rules）完整编解码
- [x] 实现 APDU（Application Protocol Data Unit）编解码，含分片
- [x] 实现 NPDU（Network Protocol Data Unit）编解码，含跳数管理
- [x] 实现 BVLC（BACnet Virtual Link Control）IPv4 编解码
- [x] 实现 BVLCV6（BACnet Virtual Link Control）IPv6 编解码
- [x] 支持自定义应用标签解析器（`CustomTagResolver`）供厂商扩展属性
- [x] 支持 `IEncode`/`IDecode` 接口供自定义数据结构序列化

**优先级**：Must

---

### 3.3 M3 - 设备发现

**描述**：在 BACnet 网络中自动发现在线设备。

**用户故事**：作为楼宇自动化工程师，我希望程序启动后自动发现网络中的所有 BACnet 设备，以便无需手动配置设备地址。

**验收条件（AC）**：
- [x] 发送 Who-Is 广播，发现网络中所有 BACnet 设备
- [x] 接收 I-Am 响应，记录设备 ID、地址、最大 APDU、分片能力
- [x] 支持指定设备 ID 范围的定向发现
- [x] 发现后自动读取设备属性列表
- [x] 定期（默认 60 秒）重新扫描，感知设备上线/下线

**优先级**：Must

---

### 3.4 M4 - 属性读写

**描述**：读取和写入 BACnet 设备对象的属性值。

**用户故事**：作为楼宇自动化工程师，我希望读取温度传感器的当前值和工程单位，并能远程写入设定点，以便实现自动控制。

**验收条件（AC）**：
- [x] 实现 ReadProperty（读取单个属性）
- [x] 实现 ReadPropertyMultiple（批量读取多对象多属性）
- [x] 实现 ReadRange（读取数组/列表的范围，如趋势日志）
- [x] 实现 WriteProperty（写入单个属性）
- [x] 实现 WritePropertyMultiple（批量写入多对象多属性）
- [x] 支持属性写入优先级（Priority Array，1-16 级）
- [x] 支持 150+ 种标准属性编号（`BacnetPropertyIds`）
- [x] 支持 65+ 种标准对象类型（`BacnetObjectTypes`）
- [ ] 支持按属性名称字符串直接读写（友好 API）

**优先级**：Must

---

### 3.5 M5 - COV 变更通知

**描述**：订阅设备属性变化，当值发生变化时主动推送通知，替代轮询。

**用户故事**：作为楼宇自动化工程师，我希望订阅二进制输入点位的状态变化，而不是每秒轮询，以便降低网络负载并提高实时性。

**验收条件（AC）**：
- [x] 实现 SubscribeCOV（订阅对象级 COV）
- [x] 实现 SubscribeCOVProperty（订阅属性级 COV，带变化阈值）
- [x] 接收 UnconfirmedCOVNotification（无确认 COV 通知）
- [x] 接收 ConfirmedCOVNotification（有确认 COV 通知）
- [x] 服务端发送 COV 通知（配合 DeviceStorage 属性变化事件）
- [ ] COV 订阅生命周期自动续约

**优先级**：Must（订阅/接收）；Should（自动续约）

---

### 3.6 M6 - 事件与报警

**描述**：处理 BACnet 事件通知、报警摘要，用于楼宇报警管理系统。

**用户故事**：作为楼宇自动化工程师，我希望接收设备的越限报警通知，以便及时响应异常情况。

**验收条件（AC）**：
- [x] 接收 EventNotification（有确认/无确认事件通知）
- [x] 发送 ConfirmedEventNotification（有确认事件通知）
- [x] 实现 GetAlarmSummary（获取报警摘要）
- [x] 实现 GetEventInformation（获取详细事件信息）
- [x] 实现 AcknowledgeAlarm（确认报警）
- [x] 解码 BacnetEventNotificationData（完整事件通知数据结构）

**优先级**：Should

## 4. 非功能需求

### 4.1 性能

- 批量读取支持自定义批大小（`BatchSize`，默认 20 个属性），避免单包超限
- 核心编解码路径（ASN.1）避免堆分配，使用 `EncodeBuffer` 池化缓冲区
- 单次 `ReadPropertyMultiple` 最大支持 1476 字节 APDU（IPv4）/ 1480 字节（IPv6）

### 4.2 兼容性

- **框架**：`netstandard2.0` + `net45`（覆盖 .NET Framework 4.5、.NET Core 2.0+、.NET 5+）
- **协议标准**：ANSI/ASHRAE Standard 135-2020 及以后版本（ISO 16484-5）
- **设备互操作**：与主流楼控品牌（约翰逊控制、霍尼韦尔、西门子楼宇、江森自控等）兼容
- **NuGet 依赖**：仅依赖 `NewLife.Core`（日志/配置/追踪）和 `NewLife.IoT`（驱动框架），无本地库依赖

### 4.3 安全

- 传统 BACnet/IP 基于 UDP，无内置加密（已知安全限制，遵循行业现状）
- 未来支持 BACnet/SC（TLS 加密）填补安全空白
- 属性写入需通过驱动层配置授权，不暴露未授权写入接口
- 不记录、不输出任何设备凭据信息

## 5. 边界与约束

### 5.1 当前版本明确不做的事情

- **硬件串口驱动**：MS/TP 和 PTP 传输代码已存在（`Transport/` 目录），但已从编译中排除。重新启用需解决跨平台串口兼容性问题。
- **BACnet Router**：不实现 BACnet 路由器功能（跨网段 NPDU 转发）。
- **BTL 认证**：不提供 BACnet Testing Laboratories 官方认证。
- **图形化工具**：本库为代码库，不提供类似 YABE 的图形化探索工具。
- **设备仿真框架**：`DeviceStorage` 仅提供基础属性存储，不模拟完整的设备行为状态机。

### 5.2 已知技术限制

| 限制 | 说明 | 所在文件 |
|------|------|---------|
| invoke-id 全局共享 | invoke-id 未按远程设备隔离，高并发多设备场景可能冲突 | `BACnetClient.cs:23` |
| 批量读取数据包大小 | 大批量对象（100+）时数据包可能超限，需手动控制 BatchSize | `Protocols/BacClient.cs` |
| 批量读取偶发 bug | 每次批量读取有时只返回 1 个点位数据 | `Drivers/BACnetDriver.cs:134` |
| 日期第 32 天 | `BacnetDate` 对 day=32（"最后一天"标记）处理未完成 | `Base/BacnetDate.cs:54` |

## 8. 术语表

| 术语 | 定义 |
|------|------|
| BACnet | Building Automation and Control Networks，楼宇自动化与控制网络协议，ANSI/ASHRAE 135 标准 |
| APDU | Application Protocol Data Unit，应用协议数据单元 |
| NPDU | Network Protocol Data Unit，网络协议数据单元 |
| BVLC | BACnet Virtual Link Control，BACnet 虚拟链路控制层（IPv4） |
| BVLCV6 | BACnet Virtual Link Control Version 6，IPv6 版虚拟链路控制 |
| BBMD | BACnet Broadcast Management Device，BACnet 广播管理设备，用于跨子网广播 |
| ASN.1 | Abstract Syntax Notation One，抽象语法标记一，BACnet 使用其 BER 编码规则 |
| BER | Basic Encoding Rules，基本编码规则，ASN.1 的一种编码方式 |
| COV | Change of Value，值变化通知，当属性值超过阈值时主动推送 |
| WhoIs | BACnet 设备发现服务，广播询问"谁在网络上" |
| IAm | BACnet 设备应答服务，响应 WhoIs 表明自己在线 |
| MS/TP | Master-Slave/Token Passing，主从/令牌传递，基于 RS485 的 BACnet 物理层 |
| PTP | Point-to-Point，点对点，基于 RS232 的 BACnet 物理层 |
| BACnet/SC | BACnet Secure Connect，基于 TLS/WebSocket 的安全 BACnet 通信 |
| BTL | BACnet Testing Laboratories，BACnet 测试实验室，负责 BACnet 产品认证 |
| PICS | Protocol Implementation Conformance Statement，协议实现一致性声明 |
| invoke-id | 请求调用标识符，用于匹配异步请求和响应，范围 0-255 |
| Priority Array | 优先级数组，BACnet 写操作支持 1-16 优先级，用于命令式覆盖控制 |
| DeviceId | BACnet 设备实例号，在 BACnet 网络中唯一标识一个设备，范围 0-4194303 |
