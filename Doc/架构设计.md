# NewLife.BACnet 架构设计

## 1. 整体分层架构

NewLife.BACnet 采用严格的五层架构，每层职责单一，依赖方向从上到下，高层调用低层，低层通过接口和事件通知高层。

```
┌──────────────────────────────────────────────────────────────────┐
│                     IoT 驱动适配层                                │
│     BACnetDriver / BACnetNode / BACnetParameter                  │
│     命名空间：NewLife.BACnet.Drivers                              │
│     依赖：NewLife.IoT.IDriver 框架接口                            │
├──────────────────────────────────────────────────────────────────┤
│                     高级协议层                                     │
│     BacClient（客户端）/ BacServer（服务端）                      │
│     BacNode / BacProperty / ObjectPair                           │
│     命名空间：NewLife.BACnet.Protocols                            │
├──────────────────────────────────────────────────────────────────┤
│                     核心协议层                                     │
│     BacnetClient（事件驱动、invoke-id 管理、分片处理）            │
│     BacnetAsyncResult（异步操作封装）                             │
│     命名空间：System.IO.BACnet                                    │
├──────────────────────────────────────────────────────────────────┤
│                     编解码层                                       │
│     ASN1 / APDU / NPDU / BVLC / BVLCV6 / Services / MSTP / PTP │
│     EncodeBuffer / EncodeResult                                  │
│     命名空间：System.IO.BACnet.Serialize                          │
├──────────────────────────────────────────────────────────────────┤
│                     传输层                                         │
│     IBacnetTransport（接口）/ BacnetTransportBase（抽象基类）     │
│     BacnetIpUdpProtocolTransport（IPv4）                          │
│     BacnetIpV6UdpProtocolTransport（IPv6）                        │
│     命名空间：System.IO.BACnet                                    │
└──────────────────────────────────────────────────────────────────┘
```

另有横切关注点：

```
┌────────────────────────────────────────┐
│            存储层（辅助模块）            │
│  DeviceStorage / Object / Property     │
│  命名空间：System.IO.BACnet.Storage    │
└────────────────────────────────────────┘

┌────────────────────────────────────────┐
│            工具层（辅助模块）            │
│  BacnetValuesExtensions                │
│  命名空间：System.IO.BACnet.Helpers    │
└────────────────────────────────────────┘
```

## 2. 传输层设计

### 2.1 接口与基类

```
IBacnetTransport（System.IO.BACnet）
├── 属性：MaxInfoFrames、HeaderLength、MaxBufferLength、Type、MaxAdpuLength
├── 方法：Start()、GetBroadcastAddress()、WaitForAllTransmits(timeout)
│         Send(buffer, offset, len, address, waitForTx, timeout)
└── 事件：MessageRecieved（接收到数据时触发）

BacnetTransportBase : IBacnetTransport（抽象基类）
├── 属性：Tracer（ITracer）、Log（ILog）——可观测性注入点
├── 方法：InvokeMessageRecieved()——触发接收事件的统一入口
└── 继承者须实现：Send()、Start()、GetBroadcastAddress()
```

### 2.2 IPv4 传输（BacnetIpUdpProtocolTransport）

```
构造函数重载：
  (port)
  (port, maxPayload, localEndpoint)
  (sharedPort, exclusivePort)          // 多进程共享

关键参数：
  SharedPort    = 47808 (0xBAC0)       // 绑定 SO_REUSEADDR，接收广播
  ExclusivePort = 0（可选）             // 绑定独占端口，用于单播响应
  dontFragment  = false                // IP 分片控制
  maxPayload    = 1472 字节             // 超出则依赖 IP 层分片
  localEndpointIp = ""                 // 空字符串时绑定 0.0.0.0

最大 APDU = 1476 字节（以太网 MTU 1500 - IP 头 20 - UDP 头 4）

BVLC 处理流程（接收方向）：
  UDP 接收 → BVLC.Receive() → 
    如是 BBMD 控制帧 → BVLC 处理（注册/转发外部设备）
    如是 NPDU 数据   → 触发 MessageRecieved 事件
```

### 2.3 IPv6 传输（BacnetIpV6UdpProtocolTransport）

```
特点：
  IPv6 地址表示：[::1]:47808
  虚拟 MAC 地址：3 字节（用于 BACnet 地址中的 MAC 部分）
  最大 APDU = 1480 字节（IPv6 头 40 字节，比 IPv4 多 4 字节可用）
  使用 BVLCV6 处理 IPv6 特定帧格式
```

### 2.4 传输层扩展

新增传输方式只需实现 `IBacnetTransport`（或继承 `BacnetTransportBase`），
然后在 `BacClient` / `BacServer` 的 `Transport` 属性中注入即可：

```csharp
var client = new BacClient
{
    Transport = new MyCustomTransport(...)
};
client.Open();
```

已禁用的传输实现（代码保留在 `Transport/`，通过 `<Compile Remove>` 排除）：

| 文件 | 协议 | 说明 |
|------|------|------|
| `BacnetMstpProtocolTransport.cs` | MS/TP RS485 | 需跨平台串口支持 |
| `BacnetPtpProtocolTransport.cs` | PTP RS232 | 需跨平台串口支持 |
| `BacnetSerialPortTransport.cs` | 通用串口 | 基础串口抽象 |
| `BacnetTransportEthernet.cs` | Ethernet 802.3 | 需原始套接字权限 |
| `BacnetPipeTransport.cs` | Windows 管道 | 进程间通信，仅限 Windows |

## 3. 编解码层设计

### 3.1 整体数据流

```
发送方向（编码）：
  应用数据（BacnetValue[]）
    → Services.Encode*()    ASN.1 BER 编码各服务参数
    → APDU.Encode*()        封装为 APDU PDU（含 invoke-id、服务码）
    → NPDU.Encode()         封装为 NPDU（含网络路由控制字段）
    → BVLC.Encode()         封装为 BVLC 帧（含 BACnet/IP 标识）
    → UDP Socket 发送

接收方向（解码）：
  UDP Socket 接收
    → BVLC.Receive()        解 BVLC 头，获取 NPDU 偏移
    → NPDU.Decode()         解 NPDU，获取网络层控制和地址
    → APDU.GetDecodedType() 确定 PDU 类型（确认/未确认/响应/错误）
    → APDU.Decode*()        解 APDU 头，获取 invoke-id 和服务码
    → Services.Decode*()    解码服务参数为 BacnetValue[]
```

### 3.2 ASN.1 编解码（ASN1.cs）

BACnet 使用 ASN.1 BER（Basic Encoding Rules）编码，但采用了专有简化的 TLV（Tag-Length-Value）格式。

**标签（Tag）结构**：
```
1 字节标签：
  高 4 位 = Tag Number（0-14，15 表示扩展标签）
  第 3 位  = Class（0=Application, 1=Context）
  低 2 位  = Length/Value类型（0=bool/0字节, 1=1字节, 2=2字节, 3=4字节, 4=扩展长度, 5=开放标签, 6=关闭标签）
```

**核心接口**：
- `encode_*()` 系列方法（约 60 个）：编码各种 BACnet 数据类型
- `decode_*()` 系列方法（约 60 个）：解码各种 BACnet 数据类型
- `CustomTagResolver` 委托：允许应用层注册自定义厂商扩展属性的解析逻辑

**IEncode / IDecode 接口**：
```csharp
// 复杂数据结构可实现此接口以支持序列化
public interface IEncode  { void Encode(EncodeBuffer buffer); }
public interface IDecode  { int Decode(byte[] buffer, int offset, uint length, BacnetObjectTypes type, uint? objectInstance); }
```

### 3.3 EncodeBuffer（编码缓冲区）

```
EncodeBuffer（System.IO.BACnet.Serialize）
├── byte[] buffer      原始字节缓冲区
├── int offset         当前写入位置
├── int max_offset     已写入最大位置（用于分片计算）
├── bool expandable    是否允许动态扩容
└── int min_limit      分片起点偏移
```

分片时通过 `min_limit` 控制当前分片段的起始位置，实现滑动窗口写入。

### 3.4 BVLC 协议（IPv4）

```
帧类型（BacnetBvlcFunctions）：
  BVLC_RESULT                         结果响应
  BVLC_WRITE_BROADCAST_DISTRIBUTION_TABLE  写 BDT 表
  BVLC_READ_BROADCAST_DIST_TABLE      读 BDT 表
  BVLC_REGISTER_FOREIGN_DEVICE        外部设备注册（FD Registration）
  BVLC_ORIGINAL_UNICAST_NPDU          原始单播 NPDU
  BVLC_ORIGINAL_BROADCAST_NPDU        原始广播 NPDU
  BVLC_FORWARDED_NPDU                 转发 NPDU（BBMD 转发）
  BVLC_DISTRIBUTE_BROADCAST_TO_NETWORK  分发广播到网络

BBMD 状态维护（BVLC 类内部）：
  _peers：List<BacnetAddress>          BBMD 对等体列表
  _foreignDevices：Dictionary<IPEndPoint, DateTime>  外部设备注册表（带 TTL）
```

## 4. 核心协议层设计（BacnetClient）

### 4.1 类职责

`BacnetClient`（`BACnetClient.cs`）是整个协议栈的核心调度类，负责：

1. **连接生命周期**：启动传输层（`Start()`），注册底层消息接收事件
2. **请求管理**：为每个请求分配 `invoke-id`（0-255 循环），并维护等待响应的字典
3. **分片处理**：发送侧将超大 APDU 拆分为多个分片；接收侧收集所有分片后重组
4. **异步操作**：基于 `ManualResetEvent` 实现同步等待，支持超时和重试（默认 3 次）
5. **事件分发**：将接收到的各类 BACnet 服务请求/响应通过 C# 事件分发给上层处理

### 4.2 invoke-id 管理

```
当前实现（全局 _invokeId，所有远程设备共享）：
  _invokeId 字段：byte（0-255 循环递增）
  _segmentsPerInvokeId：Dictionary<byte, List<Tuple<byte, byte[]>>>   分片缓存
  _locksPerInvokeId：Dictionary<byte, object>                          分片锁
  _expectedSegmentsPerInvokeId：Dictionary<byte, byte>                 期望分片数

已知问题：
  同时与多个设备通信时，invoke-id 可能重叠，导致响应匹配错误。
  TODO: invoke-id 应按远程设备（BacnetAddress）隔离。（BACnetClient.cs:23）
```

### 4.3 分片机制

BACnet 分片（Segmentation）用于传输超过单个 APDU 大小限制的数据：

```
发送分片（SegmentedRequest）：
  1. 检查目标设备的最大 APDU 和分片能力（MaxSegments）
  2. 按 ProposedWindowSize（默认10）个分片为一窗口批量发送
  3. 等待 SegmentAck，收到 ACK 后发送下一窗口
  4. 超时或达到最大重试次数则中止

接收分片（DefaultSegmentationHandling）：
  1. 收到分片数据（Sequence Number = 0 为首片）
  2. 累积到 _segmentsPerInvokeId[invokeId] 列表
  3. 收到最后一片（MoreFollows=false）后合并所有片段
  4. 将合并数据作为完整 APDU 处理
  5. 发送 SegmentAck 确认窗口
```

### 4.4 事件体系

`BacnetClient` 通过事件将接收到的 BACnet 报文分发给上层：

| 事件名 | 触发时机 | 参数 |
|--------|---------|------|
| `OnIam` | 收到 I-Am 广播 | addr, deviceId, maxAPDU, segmentation, vendorId |
| `OnWhoIs` | 收到 Who-Is 请求 | addr, lowLimit, highLimit |
| `OnWhoHas` | 收到 Who-Has 请求 | addr, deviceId, objectId |
| `OnIHave` | 收到 I-Have 广播 | addr, deviceId, objectId |
| `OnCOVNotification` | 收到 COV 通知（无确认） | addr, subscriberProcessId, initiatingDeviceIdentifier, ... |
| `OnEventNotification` | 收到事件通知 | addr, eventData |
| `OnReadPropertyRequest` | 收到读属性请求（服务端） | addr, invokeId, objectId, propertyId, arrayIndex |
| `OnReadPropertyMultipleRequest` | 收到批量读请求（服务端） | addr, invokeId, properties |
| `OnWritePropertyRequest` | 收到写属性请求（服务端） | addr, invokeId, objectId, value |
| `OnTimeSynchronize` | 收到时间同步 | addr, dateTime, utc |
| `OnError` | 收到错误响应 | addr, invokeId, errorCode |

## 5. 高级协议层设计

### 5.1 BacClient（客户端）

```
核心状态：
  _nodes：List<BacNode>         已发现设备列表（线程安全，lock (_nodes) 保护）
  _client：BacnetClient         底层协议客户端（1:1 对应）
  _timer：TimerX                定时重扫定时器（60 秒，Async=true）
  _tcs：TaskCompletionSource    Scan() 等待首个设备响应的信号源

设备发现流程：
  Open()
    ├── 初始化 Transport（默认 BacnetIpUdpProtocolTransport）
    ├── 创建 BacnetClient，注册 OnIam 事件
    ├── client.Start()（启动 UDP 监听）
    ├── Scan()（广播 WhoIs，等待 WaitingTime 毫秒）
    └── 启动 60 秒定时重扫 Timer

  OnIam 回调（在 UDP 线程上执行）：
    ├── 过滤：不是目标 DeviceId 则忽略
    ├── _tcs.TrySetResult(node)（解除 Scan() 阻塞）
    ├── 去重：检查 _nodes 中是否已有该设备
    ├── 新增节点到 _nodes
    └── Task.Run(() => GetProperties(node, true))（异步读属性）

批量属性读取（GetProperties）：
  1. ReadProperty 获取对象列表（PROP_OBJECT_LIST）
  2. 按 BatchSize（默认 20）分批调用 ReadPropertyMultiple
  3. 读取每个对象的 PROP_OBJECT_NAME、PROP_PRESENT_VALUE、PROP_UNITS、PROP_DESCRIPTION
  4. 结果填充到 BacNode.Properties 集合
```

### 5.2 BacServer（服务端）

```
核心状态：
  _client：BacnetClient         底层协议客户端
  Storage：DeviceStorage        设备对象存储

启动流程：
  Open()
    ├── 加载 XML 存储文件（DeviceStorage.Load(StorageFile)）
    ├── 设置 DeviceId 到存储对象的 DEVICE 对象实例号
    ├── 创建 BacnetClient，注册服务端事件
    ├── client.Start()
    └── client.Iam()  // 广播 I-Am 宣告自身

服务端事件处理：
  OnWhoIs     → 检查 DeviceId 范围后发送 Iam() 响应
  OnReadPropertyRequest     → DeviceStorage.ReadProperty() → SimpleAck + 属性值
  OnReadPropertyMultipleRequest → 遍历请求列表 → ReadPropertyAck
  OnWritePropertyRequest    → DeviceStorage.WriteProperty() → SimpleAck
```

### 5.3 DeviceStorage（设备对象存储）

```
数据结构：
  Objects：List<Object>
    └── Object.Properties：List<Property>
          └── Property.BacnetValue[]   // 属性值（支持数组）

XML 序列化（DeviceDescriptor.xml）：
  <DeviceDescriptor>
    <Object Type="8" Instance="666">    <!-- OBJECT_DEVICE = 8 -->
      <Property Id="77">...</Property>  <!-- PROP_OBJECT_NAME = 77 -->
    </Object>
    <Object Type="2" Instance="0">     <!-- OBJECT_ANALOG_VALUE = 2 -->
      ...
    </Object>
  </DeviceDescriptor>

钩子机制：
  OnReadProperty  委托：ReadPropertyHandler   // 应用层可覆盖默认读行为
  OnWriteProperty 委托：WritePropertyHandler  // 应用层可覆盖默认写行为
  OnWriteNotify   事件：通知属性值已变化（配合 COV）
```

## 6. IoT 驱动适配层设计

### 6.1 类关系

```
NewLife.IoT 框架（外部依赖）：
  IDriver / DriverBase
  INode
  IDriverParameter / IDriverParameterKey

NewLife.BACnet 驱动实现：
  BACnetDriver  : DriverBase        [Driver("BACnet")]
  BACnetNode    : INode             携带 BacClient 引用
  BACnetParameter : IDriverParameter  Port + DeviceId
```

### 6.2 单例连接模式

一个 `BACnetDriver` 实例对应一个 BACnet 网络连接（`BacClient`），多个设备节点（`BACnetNode`）共享该连接：

```
BACnetDriver（单例，通常由 IoT 框架创建）
├── _client：BacClient（单实例）
└── _nodes：int（引用计数）

Open(device, parameter)：
  if (_client == null)               // DCL 双重检查锁定
      lock (this)
          if (_client == null)
              _client = new BacClient(...)
  Interlocked.Increment(_nodes)
  return new BACnetNode { Client = _client, ... }

Close(node)：
  if (Interlocked.Decrement(_nodes) <= 0)
      _client.Dispose()              // 最后一个节点关闭时释放连接
```

### 6.3 点位地址格式

驱动层使用字符串格式的点位地址寻址 BACnet 对象属性：

```
格式："{实例}_{类型}"
示例：
  "0_2"   → 实例 0，类型 2（OBJECT_ANALOG_VALUE）
  "1_0"   → 实例 1，类型 0（OBJECT_ANALOG_INPUT）
  "0_5"   → 实例 0，类型 5（OBJECT_BINARY_VALUE）

解析由 ObjectPair（Protocols/ObjectPair.cs）实现。
支持点位名称字符串直接匹配（通过 BacNode.Properties 查找）。
```

### 6.4 批量读取流程

```
Read(node, points)：
  1. 解析每个点位的地址 → BacnetObjectId + BacnetPropertyIds.PROP_PRESENT_VALUE
  2. 调用 BacClient.ReadProperties(objectIds[])
  3. 将返回的 BacnetValue[] 转换为 Dictionary<string, object>
  4. 返回结果字典给 IoT 框架

已知问题：
  偶发只返回 1 个点位，原因待查（BACnetDriver.cs:134）
```

```
BacnetObjectId = Type（BacnetObjectTypes）+ Instance（uint）
```

```
BacnetAddress：

```

## 10. 关键设计决策

### 10.1 为什么 invoke-id 目前全局共享？

现有实现（`BACnetClient.cs` 第 23 行 TODO）中，`invoke-id`（0-255）对所有远程设备使用同一个计数器。在单设备场景下工作正常，但同时与多个设备通信时，不同设备的响应可能共用同一 invoke-id，导致响应匹配混乱。

**后续改进方向**：为每个 `BacnetAddress`（远程设备地址）维护独立的 invoke-id 计数器和等待队列，改用 `Dictionary<BacnetAddress, byte> _invokeIdPerDevice`。

### 10.2 为什么 MS/TP 等串口传输被禁用？

MS/TP 和 PTP 代码来源于移植自第三方实现，涉及底层串口操作。在 .NET 多框架多平台目标（netstandard2.0/net45）下，串口 API 存在兼容性差异，且需要额外测试。当前策略是保留代码，通过 `<Compile Remove>` 排除，待平台策略稳定后重新启用。

### 10.3 为什么 BacClient 使用 TaskCompletionSource 而非 ManualResetEvent？

`Scan()` 需要等待第一个 IAM 响应（异步事件），使用 `TaskCompletionSource<BacNode>` 配合 `CancellationTokenSource` 可以优雅实现超时取消语义，比 `ManualResetEvent` + `WaitOne(timeout)` 更加现代化，且不会阻塞线程池。

### 10.4 为什么存储层使用 XML 而非 JSON？

`DeviceStorage`（`DeviceDescriptor.xml`）的 XML 格式来源于原始参考实现。XML 对于描述树状对象-属性层次结构直观且易于人工编辑，适合设备描述文件场景。BACnet 标准本身也有 XML 交换格式（CSML）先例。
